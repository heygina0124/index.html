# Motion Rules

SaaS 설명 영상은 "UI가 살아 움직이는 느낌"이 핵심이고, 화려함은 적이다. 시선이 갈 곳은 한 번에 하나.

## 양
- 한 장면에서 동시에 움직이는 요소 최대 **2개**. 나머지는 순서대로 (stagger).
- 장면당 "주인공 모션" 1개 (카운트업, 행 추가, 상태 변화 등). 나머지는 그걸 돕는 조연.
- 화면이 완전히 정지한 순간이 2초 넘게 이어지지 않게. 아주 느린 카메라 드리프트(1~3%)로 숨 쉬게 한다.

## 타이밍
- 요소 등장: 0.3~0.6s. 1초 넘는 등장은 지루하다.
- stagger: 0.05~0.12s.
- 장면 전환: 0.3~0.5s. 하드컷도 OK — 매 장면마다 화려한 트랜지션 금지.
- VO가 기능 이름을 말하기 **0.2~0.4초 전에** 해당 UI가 반응해야 자연스럽다.
- 장면 끝 0.3s 전에는 새 요소를 등장시키지 않는다.

## Easing
- 기본: spring (damping 높게, 튕김 거의 없음) 또는 easeOutCubic.
- linear는 카메라 드리프트와 프로그레스 바에만.
- bounce/elastic은 CTA 버튼이나 체크마크 같은 "보상" 순간 1~2번만.

## 카메라
- 줌 범위 100~140%. 그 이상은 UI가 흐려지고 멀미난다.
- 줌인은 **설명하는 요소 쪽으로**. 이유 없는 줌 금지.
- 9:16은 UI를 통째로 줄이지 말고 해당 영역으로 크롭 + 확대. 사이드바·보조 패널은 숨긴다.

## 텍스트
- 오버레이 텍스트는 VO와 같은 말을 반복하지 않는다. 핵심 단어/숫자만 (최대 5단어).
- 최소 크기: 16:9에서 40px, 9:16에서 56px.
- 화면에 최소 1.5초 이상 머무르게.
- 9:16은 상하 각 10%를 안전 영역으로 비워둔다 (앱 UI가 덮는 영역).

## 브랜드
- 액센트 컬러는 "주목해야 할 것"에만. 배경이나 장식에 쓰지 않는다.
- 로고는 처음(선택)과 마지막 CTA에만.

## 금지
- 회전, 3D 플립, 글리치, 과한 블러 (고객이 요청하지 않는 한)
- 모든 요소에 같은 애니메이션
- 커서가 화면을 헤매는 것 — 커서를 쓰면 목적지로 곧장, 클릭은 0.15s 눌림 효과
